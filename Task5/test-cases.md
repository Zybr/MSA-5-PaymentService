# Задание 5. Тест-кейсы платёжного процесса

## Общие предусловия

- Docker и Docker Compose установлены.
- Стек запущен командой из инструкции задания 4.2.
- Java-сервис отвечает `{"status":"UP"}` на `GET /health`.
- BPMN-процесс `payment-process` успешно развёрнут в Zeebe.
- Для асинхронных сценариев состояние проверяется запросом `GET /payments/{paymentId}` до достижения конечного статуса,
  но не дольше 60 секунд.

## Интеграционные тесты

| ID     | Название                                    | Тип            | Компоненты                                                                              | Предусловия                                                                    | Действия                                                                     | Ожидаемый результат                                                                                                                                       |
|--------|---------------------------------------------|----------------|-----------------------------------------------------------------------------------------|--------------------------------------------------------------------------------|------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------|
| INT-01 | Автоматический деплой BPMN                  | Интеграционный | Docker Compose, `deploy-process`, Zeebe                                                 | Zeebe доступен; файл `process.bpmn` присутствует                               | Запустить стек и проверить `docker compose logs deploy-process`              | Контейнер завершается с кодом `0`; в логе есть `Process deployed`; в Zeebe зарегистрирован процесс `payment-process`                                      |
| INT-02 | Создание экземпляра процесса через API      | Интеграционный | `PaymentHttpServer`, `PaymentProcessService`, `ZeebeClient`, Zeebe, `PaymentRepository` | Выполнены общие предусловия                                                    | Отправить `POST /payments` с `{"scenario":"success"}`                        | HTTP `202`; возвращены непустые `paymentId`, `operationId` и `processInstanceKey`; в Zeebe создан один экземпляр процесса с теми же идентификаторами      |
| INT-03 | Синхронизация параллельных проверок         | Интеграционный | Zeebe, `PaymentWorkers`, antifraud-, compliance- и limits-воркеры                       | Создан платёж со сценарием `success`                                           | Дождаться завершения и прочитать `history`                                   | Присутствуют `FRAUD_ALLOW`, `COMPLIANCE_ALLOWED`, `LIMITS_ALLOWED`; `CREDIT_SUCCEEDED` появляется только после завершения всех трёх проверок              |
| INT-04 | Корреляция ручного решения по `paymentId`   | Интеграционный | HTTP API, `PaymentProcessService`, Zeebe message correlation, `PaymentRepository`       | Одновременно созданы два платежа `manual-review`; оба ожидают решения          | Для первого вызвать `/review` с `ALLOW`, для второго — с `DENY`              | Сообщения коррелируют с правильными экземплярами: первый получает `COMPLETED`, второй — `REFUNDED`; истории и решения не смешиваются                      |

| INT-06 | Валидация неизвестного сценария             | Интеграционный | `PaymentHttpServer`, `PaymentScenario`                                                  | Выполнены общие предусловия                                                    | Отправить `POST /payments` с `{"scenario":"unknown"}`                        | HTTP `400`; ответ содержит описание допустимых сценариев; экземпляр BPMN не создаётся                                                                     |
| INT-07 | Обращение к отсутствующему платежу          | Интеграционный | `PaymentHttpServer`, `PaymentRepository`                                                | В репозитории нет указанного идентификатора                                    | Выполнить `GET /payments/not-found`, затем `POST /payments/not-found/review` | Оба запроса возвращают HTTP `404` и `{"error":"Payment not found"}`                                                                                       |
| INT-08 | Валидация решения ручной проверки           | Интеграционный | `PaymentHttpServer`, `PaymentProcessService`                                            | Платёж `manual-review` ожидает решения                                         | Отправить на `/review` значение `{"decision":"UNKNOWN"}`                     | HTTP `400`; сообщение `decision must be ALLOW or DENY`; процесс продолжает ожидать корректное решение или cut-off                                         |
| INT-09 | Изоляция параллельных платежей              | Интеграционный | HTTP API, Zeebe, `PaymentWorkers`, `PaymentRepository`                                  | Выполнены общие предусловия                                                    | Параллельно создать не менее 20 платежей с разными сценариями                | Все `paymentId`, `operationId` и `processInstanceKey` уникальны; каждый платёж получает результат своего сценария; события разных платежей не смешиваются |
